# 06 · production — launch gates, campaign manifest, supervisors and code bundles

> **In one line:** the fail-closed orchestration layer that refused to launch until 16 named gates had hash-bound receipts, then carried a five-arm campaign through its restarts and its evaluation-precision recovery.
> **Period:** 2026-08-02 → 2026-08-05; the bundle tooling was hardened again 2026-08-16 → 2026-08-18 for subproject 08. **Status:** completed, then reused.
> **Came from / led to:** the gate list in [`../FACTORIAL_EXPERIMENT_DESIGN.md`](../FACTORIAL_EXPERIMENT_DESIGN.md) §10 → this → the live campaign `mini_cpt5_20260803T074854Z`, and later the H→G campaigns in [`../../08_targeted_8b_cpt_experiments/`](../../08_targeted_8b_cpt_experiments/).

## Why this existed

The campaign was designed to be self-advancing and unattended: five concurrent arms, 83 checkpoints each, an asynchronous evaluation service, and a 12-hour partition limit that forces at least one restart. That is only safe if authorization is a *derived artifact* — something built from receipts that each declare a passed gate — rather than a human assertion, and if every segment revalidates its inputs before a GPU process starts.

## History

- **Contract and gates.** [`campaign_contract.py`](campaign_contract.py) holds the shared fail-closed helpers, including the authoritative evaluation dtype (`float32`) and namespace (`fp32_v1`). [`write_launch_gate_receipt.py`](write_launch_gate_receipt.py) freezes a deliberately *non-authorizing* draft; [`finalize_launch_gate_set.py`](finalize_launch_gate_set.py) validates every launch semantic and emits the only authorizable gate set; [`authorize_experiment_matrix.py`](authorize_experiment_matrix.py) creates an authorized matrix only from one passing receipt per declared gate; [`build_campaign_manifest.py`](build_campaign_manifest.py) freezes the campaign only after all of them pass.
- **The stale-plan lesson.** Earlier fail-closed policy additions had changed the experiment-matrix hash without changing the scientific cadence, which silently invalidated a frozen checkpoint plan (`../evidence/checkpoint_plan_rebind_required_20260802.json`). The gate now checks exact input paths, byte sizes and hashes plus every checkpoint-row semantic — it no longer accepts a stale plan because its old hash was compiled into the code.
- **Closure and launch (08-03).** All 16 gates passed; `../evidence/final_prelaunch_closure_20260803.json` records the frozen manifest `85311d99…`, status `passed_dry_run_only` and **zero** GPU jobs at closure. The live submission followed the same day.
- **Running the campaign.** [`preflight_segment.py`](preflight_segment.py) validates a segment at job start before any GPU process launches; [`supervise_production_segment.py`](supervise_production_segment.py) monitors the five arms, retries infrastructure failures and submits the next segment only from a verified common checkpoint; [`freeze_segment_checkpoint.py`](freeze_segment_checkpoint.py) and [`gate_segment.py`](gate_segment.py) gate on five checkpoints plus all required evaluation receipts; [`freeze_common_recovery_checkpoint.py`](freeze_common_recovery_checkpoint.py) freezes the newest checkpoint common to all five arms after an infrastructure failure. The stitched trajectory shows this machinery being used: authoritative attempts 0, 2 and 4 (`../presentations/data/dataset_order_20260805/validation_trajectory.json`).
- **Evaluation backlog control.** [`watch_checkpoint_evaluations.py`](watch_checkpoint_evaluations.py) idempotently submits and monitors exact-checkpoint GreekMMLU waves; [`build_checkpoint_evaluation_backlog_batches.py`](build_checkpoint_evaluation_backlog_batches.py) and [`accelerate_checkpoint_evaluation_backlog.py`](accelerate_checkpoint_evaluation_backlog.py) drain a backlog through bounded debug allocations, one at a time.
- **Two recoveries, receipted.** [`finalize_fp32_evaluation_recovery.py`](finalize_fp32_evaluation_recovery.py) freezes the evidence and runtime binding for re-running evaluations in float32 (recording prediction flips against the bf16 series); [`finalize_exact_mapping_evaluation_recovery.py`](finalize_exact_mapping_evaluation_recovery.py) freezes the exact-parameter-mapping recovery for numerically sensitive exports, extracting agreement %, KL, total variation and top-token log-prob quantiles from the converter's own diagnostics.
- **Closing evidence.** [`preflight_final_validation.py`](preflight_final_validation.py) and [`finalize_campaign_evidence.py`](finalize_campaign_evidence.py) freeze completion of training, loss trajectories and endpoint benchmark jobs.
- **Bundles, and their later life.** [`freeze_code_bundle.py`](freeze_code_bundle.py) / [`verify_code_bundle.py`](verify_code_bundle.py) freeze and verify byte-exact immutable scientific and efficiency bundles. These two files were the part of subproject 06 that kept changing after the experiment ended: `c13dacf1` (08-16) made the verifier safe-path standalone, `772cf450` (08-18) gated minimum H-to-G profiles on a measured allocation budget, and `e79f09ca` (08-18) made bundles materialize from committed source — all on the `agent/h2g-*` branches serving subproject 08.

## Outcome

- 16/16 declared semantic gates passed; the authoritative frozen manifest is `campaign_manifest.json` with SHA-256 `85311d99f0f8a0b901d6c0895cdd00f7696ab5af8cf10e3fda2dd5b657f8cc02`.
- The campaign completed all five arms to update 38,496 with a complete evidence set, across three authoritative attempts — the recovery path was exercised, not merely written.
- The bundle freeze/verify pair became shared infrastructure for later 8B campaigns.
