# Optimal Embedding Learning Rate in LLMs: The Effect of Vocabulary Size (Hayou & Liu, arXiv:2506.15025)

**Source:** arXiv:2506.15025  |  **Topic:** Embedding LR  |  `txt/optimal-embedding-lr.txt`, `pdf/optimal-embedding-lr.pdf`

**TL;DR.** A theory+experiments paper arguing that under Adam, large vocabulary breaks muP's prediction of equal-constant embedding LR: the optimal embedding-to-hidden LR ratio should scale as sqrt(width) (the "d-rule"), so embeddings should get a substantially HIGHER learning rate than hidden layers, not a uniform one.

## Key load-bearing facts
- Central result (the 'd-rule'): in the Large-Vocabulary (LV) regime where m >> d, set the embedding LR ratio LR_emb / LR_hidden = Theta(sqrt(d)), where d is model width (embedding dim). This contradicts muP (which predicts ratio Theta(d)) and standard practice (ratio 1, i.e. uniform LR). Abstract + contributions, lines 29-34, 74-83.
- The condition that activates the rule is LARGE vocabulary relative to width (m >> d), 'a condition generally satisfied in practice' (line 777). But the MAGNITUDE of the LR ratio scales with sqrt(width d), not directly with vocab size m. Vocab size determines WHICH regime you're in (muP vs LV); width determines the size of the ratio. Do not conflate the two.
- Concrete production recipe (Table 2, LVP 'ours'): embedding LR = eta*d^(-1/2), output LR = eta*d^(-1), hidden LR = eta*d^(-1); init var: embedding d^(-1), output d^(-1), hidden d^(-1) (same init as SP/sqrt(d) std init, not muP init). So embeddings get LR larger by sqrt(d) than hidden/output. Lines 808-843.
- 1B-model validation (4.2): 24-layer dense Transformer, width d=2048, RoPE + sliding-window MQA + SwiGLU, vocab 32064, trained on 1.75T tokens (Phi-3 data). For d=2048, sqrt(d) ~= 45.3. The model with LR_emb/LR_hidden = sqrt(d) gave faster convergence + better final train loss and lower Wikitext word-PPL than the uniform-LR baseline (same LR for embeddings and rest). Figures 4-5, lines 1015-1082, Table 3 line 1755.
- Important caveat the paper itself flags: the d-rule is 'more about efficient feature learning than hyperparameter transfer' (lines 1095-1098). It improves loss but the authors are unsure the resulting limit is optimal; HP-transfer guarantees are not established. Also the small-model fit has 'significant variance around the sqrt(d) line' (lines 919-927).
- Theory is derived in a heavily simplified setting: a 2-layer linear network (embedding + projection only, no attention/MLP), SignSGD (momentum-less Adam proxy), single update step, square loss, Zipf-like token frequencies (alpha_i ~ i^-a). Extension to real transformers is argued by analogy via the residual stream, not proven (lines 778-784, 1103-1108). The key mechanism is Adam's element-wise normalization interacting with vanishing average token frequency (~1/m).
- Empirically the paper also reports that muP scaling for hidden+output LRs held robustly (LVP keeps muP's d^-1 there), and that using the SAME LR and init for hidden and output layers was best, 'contradicting muP' for the output layer (lines 267-270, 860-866). So the only change vs a standard SP/uniform setup is boosting the embedding LR.

## Citation audit — what CURRENT_HYPERPARAMETERS.md cites this for

**Claim:** Embedding LR scales with vocabulary size under Adam (cited to support a UNIFORM learning rate for embeddings and the rest of the model).
**Verdict:** `CONTRADICTED`
**Evidence:** The paper's thesis is the opposite of uniform LR. Abstract: 'in the LV regime, the optimal embedding LR to hidden LR ratio should roughly scale as Theta(sqrt(width))... different from the Theta(width) ratio predicted by muP' (lines 29-32). Contribution 3: 'we pretrain a 1B model from scratch to show that setting LR_emb/LR_hidden ~= sqrt(d) leads to significant improvement' (lines 82-83). The 1B baseline that DID use uniform LR is the loser: 'The baseline model used the conventional LLM training configuration, which applies the same learning rate to both the embedding layer and the remaining parameters... our proposed method leads to consistently faster convergence... and a better final training loss' (lines 1067-1075). Table 2 'LVP (ours)' sets embedding LR = eta*d^(-1/2) vs hidden eta*d^(-1) (lines 833-843). Separately, the paper's scaling is primarily with WIDTH d, not directly with vocab size: vocab size m being large (m >> d) is the regime-trigger condition (line 777), while the LR ratio magnitude scales as sqrt(d).
**Correction:** Do NOT cite this paper to justify a uniform embedding LR. It argues for a HIGHER embedding LR. If the project wants the paper's actual recommendation: set the embedding-layer LR larger than the hidden-layer LR by a factor of ~sqrt(width), i.e. LR_emb = sqrt(d) * LR_hidden ('the d-rule', LVP in Table 2). Also fix the framing: the paper's LR ratio scales with WIDTH (embedding dimension d), not with vocabulary size; large vocab (m >> d) is merely the condition under which this width-scaling rule replaces muP's. Treat all of this as a from-scratch-pretraining result with explicit author caveats (it is about feature-learning efficiency, not proven HP transfer; tested only on a 1B-from-scratch run, never on CPT/finetuning or on tokenizer-extension/embedding-resize).

## How we use it
"Use this as a CAUTION paper, not as support for a uniform LR. Our CURRENT_HYPERPARAMETERS.md currently miscites it: it argues for a higher embedding LR (LR_emb = sqrt(d)*LR_hidden), and its uniform-LR baseline is the control that underperforms. For Apertus-8B (width d=4096), sqrt(d)=64, so the paper would suggest an embedding LR up to ~64x the hidden LR for a large-vocab model. Three reasons NOT to mechanically adopt that here: (1) Scope mismatch - all evidence is from-scratch pretraining (1B, 1.75T tokens); our setting is continued pretraining on an already-trained Apertus-8B with a RESIZED/EXTENDED embedding matrix, which the paper never studies. A pretrained model's existing embeddings should not be hit with a 64x LR. (2) The paper itself says the rule is about feature-learning efficiency, not HP transfer, and admits uncertainty about optimality (lines 1095-1099). (3) The relevant nugget for us is narrower and well-supported: newly added Greek embedding rows (which start essentially untrained) plausibly benefit from a HIGHER LR than the frozen-ish base, and uniform LR across old+new is suboptimal in spirit. So: (a) correct the citation in CURRENT_HYPERPARAMETERS.md - this paper does not support uniform LR; (b) if anything, use it to motivate a separate, higher LR on the new-token embedding rows during CPT, decoupled from the base model LR, but tuned empirically rather than copying sqrt(d)=64; (c) record the recipe knobs (Table 2 LVP: emb LR eta*d^-1/2, hidden/output eta*d^-1, SP-style sqrt(d) init) as a reference point, flagged as from-scratch-only."
