# Efficient and Effective Vocabulary Expansion Through Multilingual Continual Pre-training (EEVE)

**Source:** arXiv:2402.14714  |  **Topic:** New-token init  |  `txt/eeve-vocab-expansion.txt`, `pdf/eeve-vocab-expansion.pdf`

**TL;DR.** EEVE expands an English-centric LLM's vocabulary for Korean using subword-based embedding initialization plus a 7-stage parameter-freezing schedule that trains new input embeddings first and progressively unfreezes outward to the full model, transferring base-model capability with under 400 global steps per stage.

## Key load-bearing facts
- Subword-based initialization (before any training): new INPUT embeddings = average of the subword embeddings composing the new token; new OUTPUT embeddings = embedding of the FIRST subword token of the new word. The output-embedding-of-first-subword trick makes the new token's pre-update logits match its first subword's logits so gradients flow through the known subword (Sec 2.2, lines 180-192, Fig 2).
- Seven training stages (Stage 0 = init, then Stages 1-7), each frozen-then-unfrozen outward: S1 new input embeds only; S2 new output embeds (lm_head) only; S3 new input + new output embeds; S4 ALL output embeds (first unfreezing of OLD/original params); S5 new input + all output embeds; S6 all layers (QLoRA used for capability preservation); S7 internal layers only as a 'cool down' (everything except embedding layers) (Sec 2.3, lines 216-312).
- Stage 4 rationale is the logit-scale claim: because all original params were frozen through S3, the authors 'assumed the logits between old and new tokenizers were differently scaled, or less optimized to be used as a whole vocabulary,' so they begin updating OLD output embeddings; 'In our preliminary experiments, we found this stage is critical for improving the model's generative capabilities' (lines 274-281).
- Training is cheap per stage: loss converged before 400 global steps at every stage; the 2.8B variant's full pre-training finishes in under two days, partly because output-embedding-only stages skip backprop through other layers (lines 419-424).
- Hyperparameters: AdamW, cosine LR with 10-step warmup; LR 4e-5 for 10.8B, 2e-4 for 2.8B; bf16; 8xH100-80GB. 10.8B: seq len 4096, grad-accum 4, micro-batch 8. 2.8B: seq len 2048, grad-accum 16, micro-batch 16 (lines 407-424).
- Corpus and tokenizer scale: ~3.2M docs / 6.7GB Korean-heavy corpus with perplexity / n-gram-repetition / stopword filtering, and docs lacking the new tokens were filtered out to train new tokens efficiently. Vocabulary expansion gave ~3x reduction in token consumption for Korean text (lines 165-169, 322-329). Base models: SOLAR-10.7B and Phi-2; codebases Axolotl (pretrain) + LLaMA-Factory (finetune).
- Motivating caveat from the paper itself: new embeddings normally 'require trillions of training tokens' (citing Zhao et al. 2024); EEVE's whole point is to sidestep that via init + staged freezing (lines 50-52). The method is a technical report on a Korean case study, not a controlled ablation of each stage.

## Citation audit — what CURRENT_HYPERPARAMETERS.md cites this for

**Claim:** Staged-freeze recipe for vocabulary expansion.
**Verdict:** `CONFIRMED`
**Evidence:** Sec 2.3 'Multi-stage Training' (lines 216-312) and Figure 1 (lines 194-211, 'Training stages with parameter freezing. The fire and snowflake emojis indicate the trainable and frozen parameters respectively') lay out an explicit staged-freeze recipe. Abstract/intro: 'design seven training stages with parameter freezing, which elaborately adjust the order and amount of parameters to be trained... initially focusing on the training of only input embeddings and progressively expanding to encompass the full parameters in the final stage' (lines 58-63). Concrete schedule: S1 new input embeds, all else frozen (lines 222-224); S2 new output embeds only (lines 245-249); S3 new input+output embeds (lines 256-273); S4 all output embeds (lines 274-281); S5 new input + all output embeds (lines 282-295); S6 all layers (lines 296-304); S7 internal layers / 'cool down' (lines 305-312).

**Claim:** Old output embedding rows must eventually unfreeze for logit-scale matching.
**Verdict:** `PARTIAL`
**Evidence:** Stage 4 (lines 274-281) directly states this: 'As all the original parameters of the base model were frozen until this stage, we assumed the logits between old and new tokenizers were differently scaled, or less optimized to be used as a whole vocabulary. To this end, we begin to allow the update of the old parameters, specifically the output embeddings of old tokens here, making the model better generate the new tokens. In our preliminary experiments, we found this stage is critical for improving the model's generative capabilities.' This confirms old output embeddings ARE unfrozen and the motivation IS logit-scale mismatch between old and new tokenizers.
**Correction:** Soften 'must' and 'logit-scale matching'. The paper frames it as an ASSUMPTION ('we assumed the logits... were differently scaled') validated only by 'preliminary experiments,' not a proven requirement; there is no controlled ablation showing the model fails without it. 'Logit-scale matching' overstates the mechanism: the paper says old vs new logits are 'differently scaled, OR less optimized to be used as a whole vocabulary' — i.e. a looser claim about old output embeddings being poorly calibrated to coexist with new ones, not a precise scalar-rescaling operation. Doc should read: 'EEVE found it critical (in preliminary experiments) to unfreeze the OLD output embeddings at Stage 4 to fix a presumed scale/calibration mismatch between old and new tokenizer logits and improve generation of new tokens.'

## How we use it
"Use EEVE as the named prior for our Apertus-8B Greek embedding-resize + CPT staging, with three concrete carry-overs and three caveats. CARRY-OVERS: (1) Initialization, decoupled from tie_word_embeddings=false in our GLOBAL_DECISIONS: init new Greek INPUT rows as the mean of their constituent subword (merge-rule) embeddings, and init new OUTPUT rows from the FIRST subword's output embedding so a new token's initial logits track a known subword. (2) Staged unfreeze order: train new input embeds -> new output embeds -> both -> THEN unfreeze old output embeddings (EEVE Stage 4) -> all output embeds -> all layers -> internal-only cool-down. The load-bearing, paper-supported decision for us is that the OLD output-embedding rows should be unfrozen at some point to correct old/new logit-scale mismatch; cite EEVE Stage 4 (lines 274-281) for that, but flag it as a preliminary-experiment finding, not a proven requirement. (3) Cheap-stage budgeting: output-embedding-only stages skip backprop through the trunk, and EEVE saw loss converge before 400 global steps per stage — useful for sizing our CPT stage budgets. CAVEATS to record in CURRENT_HYPERPARAMETERS.md: EEVE is Korean SOLAR/Phi-2, ~6.7GB corpus, no per-stage ablation, and uses add-token-style vocab growth; our path is merge-rule extension on a different base, so transfer the SCHEDULE LOGIC, not the exact LRs (4e-5/2e-4) or the QLoRA Stage-6 choice without our own validation. Do not let the doc claim EEVE 'proves' the old-embedding unfreeze is mandatory or that it performs exact logit-scale matching."
