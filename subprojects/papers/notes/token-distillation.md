# Token Distillation: Attention-Aware Input Embeddings for New Tokens (Dobler, Elliott, de Melo; ICLR 2026; arXiv:2505.20133)

**Source:** arXiv:2505.20133  |  **Topic:** New-token init  |  `txt/token-distillation.txt`, `pdf/token-distillation.pdf`

**TL;DR.** A cheap, training-free-at-the-body method that initializes INPUT embeddings for newly added tokens by distilling (MSE-matching) the frozen model's hidden states between the new single-token sequence and its original-subtoken tokenization — outperforming subtoken-mean, NTP tuning, and even pretrained ZeTT hyper-networks without learning output embeddings.

## Key load-bearing facts
- Core objective (Eq. 1, lines 241-263): optimize ONLY the new input embedding e* by minimizing MSE between the frozen model's hidden states H^(l) on the original-subtoken tokenization (teacher) and on the new single-token sequence, summed over positions that attend to the new token. The Transformer body is FROZEN throughout (line 185-186).
- Default target layer = the LAST layer (line 265: 'we simply use the last layer's hidden state'). They deliberately keep the last layer in main experiments to avoid a model-specific sweep (line 1380), though Section 5.3 / Fig 2 shows earlier layers (even layer 4) can match or beat it and are faster.
- Output embeddings are NOT learned by the distillation objective and CANNOT be (lines 285-287: 'we do not learn output embeddings with our distillation-based objective. In fact, this is not possible, as our new tokens are not part of the original model that serves as the teacher'). For output rows you separately add an NTP objective, use any other init method, set them to zeros, or leave tokens input-only.
- Recipe knobs: AdamW, constant LR with linear warmup, no weight decay, per-method LR sweep. Init budget = max 25 snippets/token truncated to 50-token context (main) -> 2,500 tokens initialized in <10 min on one H100; a larger 100-snippets/token budget is used for the harder French/Arabic vocab-adaptation runs (lines 296-304).
- Context retrieval: main approach pulls real snippets containing the target token from a domain/general corpus via Aho-Corasick (lines 276-279); fallback generates snippets by prompting the model. Random corpus sampling is rejected as inefficient because new tokens are rare per batch (lines 270-275).
- Results: beats subtoken-mean, NTP (even with original embeddings frozen), and pretrained ZeTT hyper-networks in zero-shot tokenizer-transfer eval — without any hyper-network pretraining (lines 924-934). Token compression: ~36% fewer tokens on Arabic (Mistral-7B) -> up to ~50% compute savings due to quadratic attention (lines 1028-1030).
- Caveat on closing the gap: as initialization alone Token Distillation does NOT fully reach original-tokenization quality on hard cases; a 'moderate continued-training phase' (AdaptiVocab-style: trains the embedding matrices PLUS the first and last Transformer layers, 1,000 steps ~260M tokens, LR 5e-5) is what lets it match/exceed the original tokenizer while keeping the token-count reduction (lines 1034-1035, 1216-1218, 2589-2593).
- Stability insight (lines 905-919): NTP-tuning ALL embeddings degrades the original token embeddings and underperforms even subtoken-mean; freezing original embeddings (optimizing only new rows) helps. They note masking gradient updates to original embeddings is uncommon even in standard 'embedding tuning' warm-up phases, and flag it as useful but under-explored — explicitly 'future work'.

## Citation audit — what CURRENT_HYPERPARAMETERS.md cites this for

**Claim:** Token Distillation distills the INPUT embedding rows E (at a chosen target layer depth) and LEARNS the OUTPUT rows U by cross-entropy (learn_output_with_ce). i.e. it trains BOTH E and U.
**Verdict:** `OVERSTATED`
**Evidence:** Eq. 1 (lines 241-263) and line 907 ('for Token Distillation, we only optimize new token embeddings') show the method optimizes ONLY the new INPUT embedding e* via MSE on hidden states, with the body frozen (line 185). Output embeddings are explicitly NOT part of the distillation: lines 285-287 'Since our method backpropagates gradients back from the hidden states, we do not learn output embeddings with our distillation-based objective. In fact, this is not possible, as our new tokens are not part of the original model that serves as the teacher.' Lines 287-295: learning output rows is an OPTIONAL, separable add-on ('we can simply add a next-token prediction objective just for the output embeddings ... or freely combine our method with any other method for initializing output embeddings'), and one may even set output rows to zeros or keep tokens input-only. On the target layer: the default is the LAST layer (line 265), not a per-model 'chosen depth' — they keep last layer specifically to avoid a model-specific sweep (line 1380).
**Correction:** Token Distillation itself trains ONLY the input row E_new (MSE hidden-state matching against the frozen teacher); it does not and CANNOT train output rows U with its distillation objective. Learning U via cross-entropy is a SEPARATE, optional companion step the paper mentions ('add an NTP objective just for the output embeddings'), not part of the distillation. The doc should say: 'Token Distillation distills the input rows E (MSE to frozen hidden states, last layer by default); output rows U are handled separately/optionally — e.g. an NTP/CE objective on U only, another init method, zeros, or input-only tokens.' The 'learn_output_with_ce' framing is a config-side composition choice, not a paper claim that the method jointly trains E and U.

**Claim:** Its body-frozen relearning at init makes a separate embedding-stabilization phase unnecessary.
**Verdict:** `UNSUPPORTED`
**Evidence:** The paper never claims a separate stabilization/warm-up phase becomes 'unnecessary.' It frames Token Distillation as an INITIALIZATION ('aimed to serve as an initialization rather than as full-scale further training', line 300; zero-shot tokenizer-transfer eval, lines 333-335). It explicitly STILL uses downstream training when quality matters: 'a short continued training phase after initializing new embeddings' (line 336) and a 'moderate continued-training phase for vocabulary adaptation' (lines 1034-1035) that trains embedding matrices PLUS the first and last Transformer layers (lines 1034-1035, 2589-2593). As init-only, it 'does not yet match the original tokenization' on hard cases (line 1033) and only matches/exceeds it AFTER that continued training (lines 1216-1218). The closest supporting evidence — that freezing original embeddings avoids the degradation seen when NTP-tuning all embeddings (lines 905-919) — is offered as an observation and is explicitly left to 'future work', not asserted as eliminating a stabilization phase.
**Correction:** Replace with: 'Token Distillation provides a high-quality input-embedding INITIALIZATION that reduces reliance on a random-init warm-up; the body is frozen during the distillation step itself. The paper does NOT claim a downstream embedding-stabilization/continued-training phase is unnecessary — on harder vocab-adaptation cases it still runs a moderate continued-training phase (embeddings + first/last Transformer layers, ~1k steps/~260M tokens, LR 5e-5) to match the original tokenizer. Use Token Distillation to replace random-init warm-up, not to skip stabilization.'

## How we use it
For the Apertus-8B Greek CPT project, treat this paper as the recipe for INITIALIZING the input-embedding rows of our newly merged Greek BPE tokens (the merge-rule extension over Apertus' 131,072 vocab), not as a justification for a one-shot embedding solution. Concretely: (1) Use Token Distillation to seed E_new for each added Greek token by MSE-matching the frozen Apertus hidden states (last layer is the safe default; consider an early-layer sweep only if we want the speedup) against the token's original Apertus subtoken tokenization, pulling Greek snippets (Aho-Corasick over GlossAPI/HPLT) at ~25-100 snippets/token. This is a strong, cheap alternative to random-init + warm-up. (2) Do NOT assume this trains the output (unembedding) rows — Apertus ships tie_word_embeddings=false (per our GLOBAL_DECISIONS), so U_new must be handled separately: either an NTP/CE objective on the new output rows only, a separate init, or zeros. The config's 'learn_output_with_ce' is a legitimate composition but it is OUR pipeline step, not something Token Distillation does jointly. (3) Keep our embedding-stabilization / CPT phase: the paper itself follows init with a moderate continued-training pass (embeddings + first/last layers) to actually close the gap to the base tokenizer — so frame Token Distillation as the init that makes our stabilization phase converge faster/cheaper, and correct any doc language implying it removes the stabilization phase. (4) Borrow the freeze-original-embeddings caveat (lines 905-919): when we do tune embeddings, masking gradients on the original Apertus rows avoids degrading them — directly relevant since GLOBAL_DECISIONS requires preserving first-1000 ids and base behavior.
