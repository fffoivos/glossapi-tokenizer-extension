# 02.2.2 — Vocab language attribution

> **In one line:** a one-day distributed run that tokenised ~1 B tokens of each of 1,933 languages through Apertus's tokenizer and counted per-token firings, followed by five days of analyses that turned the 113 B-firing histogram into per-language token sets the rest of the program consumed.
> **Period:** 2026-05-13 (run) → 2026-05-18 (last analysis). Commits `002bddc5`, `719d3834`, `0bbd93de`, `7deea009`. **Status:** completed; the PMI promotion pass is the surviving canonical output.
> **Came from / led to:** this + [`02_2_1`](../02_2_1_char_language_membership/) → PMI promotion → [`02_1_4_cutoff_analysis`](../../02_1_tokenizer_experiments/02_1_4_cutoff_analysis/), [`02_1_7_intrinsic_eval_sweep`](../../02_1_tokenizer_experiments/02_1_7_intrinsic_eval_sweep/), `03_1_greek_embedding_diagnostic`

## Why this existed

Deciding how much Greek vocabulary to add to Apertus required knowing how much vocabulary Apertus already spends on each language it knows. Script-based heuristics answer that for Greek or Korean and collapse entirely for Latin script, where every language shares the same codepoints and everything falls into an "English-baseline" bucket ([`RUN_REPORT.md`](RUN_REPORT.md) § motivation). Token-level language ID is hopeless — BPE tokens are too short. The chosen approach was to trust the source dataset's own per-language partition as the label and simply *count*: run a fixed budget of each language's text through the tokenizer and record which of the 131,072 vocab entries fire, and how often.

## History

### 2026-05-13 — the run

Eight `c4-highcpu-192` workers (192 vCPU / 384 GB each, 1,536 vCPUs total) in `europe-west4-b`, 2 on-demand plus 6 spot, partitioned by `sha1(key) % 8`. Per canonical key: shuffle with `seed=42`, tokenise with `add_special_tokens=False` up to a **1 B-token cap**, `np.bincount` the ids. Eight sources: FineWeb-2 (1,811 languages), FineWeb-2-HQ (20), Clean-Wikipedia (319), EuroParl (21 EU languages), ParaDocs (18 `en-XX` pairs), FineWeb-Edu, FineWeb-HQ, DCLM-Edu; code and math deliberately excluded. Result: **1,933 canonical keys**, a `(1933, 131072)` int64 matrix at 58.4 MB compressed, **113.4 B total firings**, finished 16:37:59 UTC, ~2.5 h wall, ~$100–110 ([`RUN_REPORT.md`](RUN_REPORT.md)).

Five operational problems were solved in flight and are recorded because they are the reusable part: the C4 family's ~384 vCPU regional cap forced the 6-spot mix; Hugging Face's 1,000-requests-per-5-minutes limit was hit by a naive driver making ~12,000 listing calls (one worker reported DONE with 5 valid files out of 241 languages), fixed by pre-caching a 31,750-path `file_listings.json` so the run made zero listing calls; a GCS 403 traced to `devstorage.read_only` baked into instance metadata forced a pivot to tar-over-SSH pulls on a ~4-minute cadence; plus gcloud auth expiry and a monitor-tool timeout. HF tokens were stripped from the instances before stopping them.

Two deliberate non-outputs, on the owner's direction: the aggregator does **not** emit `primary_lang`, `signature_entropy`, or confidence flags. The raw histogram carries the full information and every cutoff is a downstream decision. One known defect was never fixed: the driver's skip-if-exists logic fossilised **4 zero-sum keys** (`chy_Latn`, `gan_Hani`, `abs_Latn`, `kon_Latn`); the planned re-run does not appear in any later commit.

### 2026-05-13/14 — first reviews: Greek, English, German

- **Greek** ([`analysis/greek_review/README.md`](analysis/greek_review/README.md)): 76.3 % of the vocab fires at all in a 1.003 B-token Greek sample; **88.56 % of Greek mass sits in the 1,507 Greek-script tokens**, the other 11.44 % in universal substrate that a Greek-focused extension should not touch. Only **3** Greek-script tokens are dormant (`▁μ`, two `▁μg` variants — scientific-notation patterns the FineWeb-2-HQ quality filter removed), so there is no vocab waste to reclaim. Token id 1206 (`�`) firing 927,670 times exposed encoding damage in some Greek source documents.
- **English** ([`analysis/english_review/membership_report.md`](analysis/english_review/membership_report.md)): joining the char masks with the firing counts gives the project's highest single-rule coverage — "en-capable" captures **99.51 %** of English mass. The structural finding is that **nothing is uniquely English**: popcount-1 tokens carry 0.07 % of English mass, because ASCII is a subset of every Latin locale's CLDR exemplar. The natural English signature is popcount 28 (69.07 % of mass). A follow-up ([`analysis/english_review/firing_rate_mapping_report.md`](analysis/english_review/firing_rate_mapping_report.md)) reframed the bitmask as an *exclusion* device only and looked for a frequency cutoff — and found **no knee**: the log-log rank-frequency curve is near-linear, so the cutoff is a "graceful menu" and was left undecided.
- **German** ([`analysis/german_review/firing_rate_mapping_report.md`](analysis/german_review/firing_rate_mapping_report.md)): English and German share 81,750 of their fired Latin tokens, Jaccard 0.9415 — which the report itself calls misleading, since only **2 of the top 50** Latin tokens are shared and per-token rate ratios swing by ~30,000× either way (`the` de/en = 0.010; `der` = 352). This produced the division of labour the rest of the program adopted: **the bitmask excludes and shapes the rule; the firing rate does the mapping.**
- **German tiers** ([`analysis/german_review/tiered_attribution_report.md`](analysis/german_review/tiered_attribution_report.md)): the first and only implementation of the [`02_2_3`](../02_2_3_token_classification/) tier policy. T0 (char-evidenced German) = **103 tokens, all ß-bearing, 0.49 % of mass**; T2 (premise) = 84.06 %; T3 substrate = 15.26 %. **T1 is exactly 0**, and that is a finding rather than a bug: CLDR exemplars either pin to one locale or spread across families, so the Germanic-Latn band never carves itself out. Headline asymmetry: German has a tiny inviolable character signature, English has none.

### 2026-05-14 — the review that changed the corpus

[`analysis/german_review/REVIEW_ISSUES_20260514.md`](analysis/german_review/REVIEW_ISSUES_20260514.md) logged six reviewer findings and closed with "**No code changes applied yet — awaiting direction.**" Issue 1 is the consequential one: `deu_Latn` and `ell_Grek` are 100 % FineWeb-2-HQ while `eng_Latn` is 100 % Clean-Wikipedia, because the English caps were exhausted. Every German-vs-English contrast in the reports above is therefore **partly domain-attributable**, including "German has more Latin and less substrate because of compound nouns". The recommended minimum was relabelling; the correct fix was a matched-corpus re-run. The other five: a mislabelled "family" bucket that should read `script_and`; a viz histogram that silently drops ~3,500 German-only tokens outside its fixed bin edges; `N_LANG_BITS = 55` hardcoded in four places; the viz skipping T1 instead of sharing tier logic; and stale numbers (German sample 1,005,777,069 vs the correct 1,005,786,784).

### 2026-05-15 — the fix, and the canonical pass

English was re-tokenised from FineWeb-HQ and merged as a **new** row rather than a replacement: `scripts/merge_eng_fineweb_hq.py` appends `eng_Latn_fineweb_hq` and leaves the wiki-only `eng_Latn` at index 1275 for backward compatibility, taking the matrix to **1,934 × 131,072**. [`analysis/language_isolation/README.md`](analysis/language_isolation/README.md) then *measured* the confound: at premise level the two English samples differ by **2,285 tokens and +6.6 pp of mass**. It also generalised the German tiering to any key, emitting three sets per language on the assumption spectrum — `strict` (T0), `premise` (T0∪T2), `premise_sub` (T0∪T2∪T3) — with German strict = 103 / 0.49 % and both English strict sets empty by structure.

The same day, [`analysis/main_token_sets/`](analysis/main_token_sets/) shipped an English/German two-language prototype and was immediately superseded by [`analysis/main_token_sets_pmi/`](analysis/main_token_sets_pmi/), the multi-language PMI pass built to [`../02_2_4_language_category_promotion/PMI_PROMOTION_SPEC.md`](../02_2_4_language_category_promotion/PMI_PROMOTION_SPEC.md): 87 cap-hit keys (≥ 1 B firings), `α = 0.5`, `δ = 1.0`, `min_count = 100`, marginal total 87,843,958,530, built at `2026-05-15T15:31:54Z` against char-tool schema v5. Three files per key — masked (Variant A), unmasked (B), delta (B\A) — 261 in all, plus `summary.tsv`, `overlap_matrix.tsv` and `uncovered_tokens.tsv`.

Two more analyses landed alongside: [`analysis/membership_rejection/`](analysis/membership_rejection/) applied the char masks across all 1,933 rows under a deliberately asymmetric three-way rule (direct language bits = hard rejection; `partial_utf8`/`byte_unmapped`/`special` = *not* rejections, reported separately; script-proxy bits = coarse signal only), and [`analysis/script_family_composition/`](analysis/script_family_composition/) built the per-script mass composition tables.

### 2026-05-18 — the ranking table for the cutoff decision

Commit `7deea009` ("Document tokenizer cutoff decision workflow") added [`analysis/main_token_sets_pmi/TOP_LANGUAGES_BY_VOCAB_SHARE.md`](analysis/main_token_sets_pmi/TOP_LANGUAGES_BY_VOCAB_SHARE.md) and its builder — every cap-hit language ranked by masked-set size and again by *unique*-set size, with the two English keys merged into one row (union 23,774 tokens). Its structural finding is clean: **all 16 effectively-script-alone languages climb in the unique ranking, and all 37 droppers are on a shared script**. Greek goes from rank 42 by size (1,479 tokens, 1.13 % of vocab) to rank 8 by uniqueness (100 % unique). The caveat it insists on: the sets overlap heavily — they sum to 140.8 % of the vocab — while their union covers 86.35 %.

## Outcome

- **The histogram**: 1,934 × 131,072 int64. The 1,933-key run totalled **113.4 B firings** ([`RUN_REPORT.md`](RUN_REPORT.md)); with the appended `eng_Latn_fineweb_hq` row the grand total is **114.37 B** ([`../CHECKPOINT_LANGUAGE_ATTRIBUTION_20260515.md`](../CHECKPOINT_LANGUAGE_ATTRIBUTION_20260515.md) § 1). The 87 cap-hit keys carry ~88 B of it; 4 keys are permanently zero.
- **The canonical per-language token sets**: 87 × 3 files under `analysis/main_token_sets_pmi/tables/`, covering **113,184 of 131,072 tokens (86.35 %)**; the 17,888 uncovered are classified by reason in `uncovered_tokens.tsv` (990 special, 1,448 byte-fragment, 4,014 substrate, 22 no-locale-admits, 3,717 below min_count, **7,463 PMI-below-δ**, 134 never-fire, 100 non-cap-hit-only).
- **Carried forward**: `summary.tsv` anchors the comparable-language footprint table in [`../../02_1_tokenizer_experiments/02_1_4_cutoff_analysis/REPORT.md`](../../02_1_tokenizer_experiments/02_1_4_cutoff_analysis/REPORT.md) § 1 and selects evaluation languages in `02_1_7_intrinsic_eval_sweep`; the `__masked.txt` tables are parsed directly by `03_1_greek_embedding_diagnostic/scripts/build_groups_perlang_v3.py` (11 languages) and `build_groups_88lang_v4.py` (the 75 with non-empty masked sets); `outputs/lang_metadata.json` supplies the power-law fit in `03_3_cscs_experiments_kickoff/POLYTONIC_VOCAB_BUDGET_CHECK.md`.
- **Left open**: the 4 zero-sum keys, the matched-corpus re-run for languages other than English, and five of the six `REVIEW_ISSUES_20260514` items — no later commit records them being applied.
- **Not in the repo**: `outputs/` and `staging/` are gitignored repo-wide, as are `*.npz`, `*.parquet` and `*.jsonl`. So `histogram_matrix.npz`, `token_metadata.parquet`, `lang_metadata.json`, `per_token_pmi.parquet`, the `language_isolation` `.jsonl` sets and the two viz `data.json` files are absent and must be regenerated. Only the derived TSV / JSON / TXT / PNG summaries are tracked.
